# 霓虹网格风格系统

## 1. 视觉目标

风格关键词是：深色数字空间、清晰几何、克制霓虹、紧凑信息和有含义的反馈。

画面首先必须可读，其次才是发光。背景承担空间感，青色承担操作感，金色承担奖励感，红色承担危险感。装饰色不能取代信息层级。

## 2. 颜色令牌

所有 DOM 色彩由 `src/styles/tokens.css` 定义，Canvas 启动时读取同一组 CSS 自定义属性。

| 令牌 | 默认值 | 语义 |
| --- | --- | --- |
| `--color-page` | `#030306` | 页面最深背景 |
| `--color-shell` | `#080914` | 应用容器背景 |
| `--color-world` | `#0d0d1a` | 游戏世界底色 |
| `--color-panel` | `#101827` | 面板和控件底色 |
| `--color-primary` | `#00ffcc` | 主交互、玩家可控状态 |
| `--color-secondary` | `#00aaff` | 信息、能量、次级交互 |
| `--color-magic` | `#ff00cc` | 特殊事件和稀有状态 |
| `--color-reward` | `#ffd34d` | 奖励、货币、关键收益 |
| `--color-danger` | `#ff405d` | 伤害、危险、阻断状态 |
| `--color-text` | `#efffff` | 主文字 |
| `--color-muted` | `#7e88a7` | 辅助信息和禁用状态 |

新增色彩前先判断是否已有语义令牌可用。不要在组件中随意创建相近青色，也不要让洋红或金色占据大面积背景。

## 3. 形状

- 世界对象使用圆角方块、菱形、短线和圆点，保证小尺寸识别度。
- 普通控件圆角 6-8px，大型浮层最多 12px。
- 常规边框 1px，重要状态可用 2px。
- UI 填充使用深色半透明层，不依赖厚重卡片。
- 游戏网格保持低对比度，只提供空间节奏。

## 4. 光效

- 常驻对象发光半径为 4-10px。
- 当前焦点、奖励或危险提示可提高到 12-18px。
- 发光颜色必须与对象语义色一致。
- 同一对象最多使用一个主发光和一个内部高光。
- 全屏闪光、粒子爆发和强调动画应在 700ms 内明显衰减。

不要使用无意义的模糊光球、背景散景或覆盖全屏的高饱和渐变。

## 5. 排版和信息密度

- 游戏世界占据首屏主体。
- HUD 保持单行或短行，优先显示状态和关键数值。
- 大字号只用于真正的启动画面；运行中标题保持紧凑。
- 主文字高亮，说明文字降到灰蓝色。
- 文本不使用负字距，也不根据视口宽度缩放字号。

## 6. 动效节奏

| 类型 | 建议周期 | 用途 |
| --- | --- | --- |
| 控件响应 | 120-220ms | 按下、切换、确认 |
| HUD 反馈 | 220-400ms | 数值变化、获得状态 |
| 实体强调 | 400-700ms | 出现、受击、拾取 |
| 呼吸光 | 2.4-3.2s | 当前目标或能量状态 |
| 环境移动 | 12-16s | 低频网格漂移 |

游戏内运动应由状态驱动，CSS 动画只负责环境和界面反馈。始终支持 `prefers-reduced-motion`。

## 7. 图层顺序

```text
世界底色
  -> 静态网格与地形
  -> 奖励和可交互目标
  -> 危险区域
  -> 可控对象和其他实体
  -> 粒子与短时反馈
  -> DOM HUD 和系统控件
  -> 模态遮罩
```

HUD 使用紧凑半透明背景，避免覆盖可控对象。需要遮挡检测时，优先移动 HUD 或降低不透明度，而不是隐藏关键信息。

## 8. 风格验收

- 黑暗环境下主体轮廓仍清晰。
- 青、蓝、金、红的语义在所有页面一致。
- 去掉发光后，形状和对比度仍足以辨认对象。
- 手机窄屏和矮屏没有文字溢出或控件重叠。
- 静态状态没有无目的动画。
- 减少动态效果设置生效。
- Canvas 与 DOM 使用同一套颜色令牌。
